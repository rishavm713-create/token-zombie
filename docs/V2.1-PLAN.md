# TZ v2.1.0 plan: one combined system (owner approved the direction 2026-11-25)

Rule: each source is either copied (MIT/Apache/BSD, with a NOTICE entry) or rebuilt
black-box with REA so TZ's version gives the same result. GPL/AGPL/noncommercial/ELv2/BUSL: ideas or black-box only, no code.
Every item ships with a tzab A/B and is labelled MEASURED / EST / UNKNOWN. No savings claims without a run.

Main cost target: context re-sent on every call (~276M tokens/day, mostly cache reads).

## Working together (owner 2026-11-25)
Goal: draw on all 36 reviewed repos. The ones with something useful get combined into one TZ with no clashes. Rejected repos stay in the ledger with the reason they were rejected.
- One owner per hook point: every feature registers through TZ's single hook dispatcher, never adds its own PreToolUse/PostToolUse entry; order is fixed and tested.
- No double work: a feature that overlaps an existing one replaces or extends it (e.g. dup-read deny extends the dup-read warning), never runs beside it.
- Conflict test: one tzab run with all features on must be at least as good as each feature alone (tokens and task pass rate); a feature that makes the combined run worse is switched off.

## Combined benchmark (usable by us)
- The repos' benchmarks are reused as method, not as claims: TokenEconomizer's SWE-Bench arm comparison (MIT scripts),
  token-optimizer's comprehension check (idea), harbor's task runner (per ledger).
- Our runner stays bin/tzab.py: arms = TZ off / each feature / all on, same tasks, same token cap, results labelled MEASURED.
